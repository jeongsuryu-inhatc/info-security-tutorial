# week13 — ShopGuard 종합 보안 정책 (초안)

> 학기 전체 실습(4~12주)에서 발견한 취약점과 방어를 정책으로 체계화한다.
> 각 정책은 **실습 근거(주차)** 를 인용한다.

## 1. 접근 통제 정책 (2·8주 연계)

- **인증**: 모든 관리자 기능은 인증된 관리자만 접근한다. 세션은 서버가 발급·검증하며,
  민감 작업 전 재인증을 요구한다.
- **인가(권한)**: 리소스 접근 시 **소유자/권한을 서버에서 검증**한다. 식별자 추측으로 타인 데이터에
  접근하는 IDOR 을 금지한다. *(근거: 8주차 `/orders/:id` IDOR → 소유자 검증 추가)*
- **최소 권한**: DB 계정·서비스 계정은 필요한 최소 권한만 부여한다.
- **관리자 행위**: 대량 변경(WHERE 없는 UPDATE 등)은 차단·승인·경보 대상. *(근거: 11주차 전체 주문 조작)*

## 2. 암호화 정책 (7·8주 연계)

- **저장(at rest)**: 비밀번호는 **복호화 불가능한 해시(bcrypt, cost ≥ 12)** 로만 저장한다. 평문 저장 금지. *(근거: 7주차 마이그레이션)*
- 개인정보(PII: 전화번호 등)는 **AES-256-GCM** 으로 암호화 저장한다. *(근거: 7주차 `aes.js`)*
- **전송(in transit)**: 모든 통신은 **HTTPS(TLS)** 로 암호화하고 **HSTS** 를 적용한다. 평문 HTTP 금지. *(근거: 8주차 `server-secure.js`)*
- **키 관리**: 암호화 키는 **환경변수/시크릿 매니저**로 주입한다. 소스·깃 커밋 금지, 주기적 교체.

## 3. 로깅·모니터링 정책 (9·11주 연계)

- **탐지**: IDS(Suricata) 로 SQLi·포트스캔·브루트포스를 탐지하고 룰을 주기적으로 튜닝한다. *(근거: 9주차 커스텀 룰)*
- **로그 보존**: 접근/인증/DB 쿼리 로그를 무결성(해시) 보장하에 보존한다. 로그 위변조를 방지한다. *(근거: 11주차 타임라인 재구성)*
- **경보**: 관리자 대량 변경, 인증 우회 성공, 비정상 로그인에 실시간 경보.

## 4. 개발 보안 정책 (4·5주 연계)

- **입력 검증**: 모든 외부 입력은 **경계에서 검증**한다(스키마 기반, zod 등). *(근거: 5주차 `utils-safe.js`)*
- **쿼리**: DB 접근은 **Prepared Statement(파라미터 바인딩)** 만 사용한다. 문자열 결합 쿼리 금지. *(근거: 4주차 SQLi 패치)*
- **위험 함수 금지**: 셸 문자열 실행(`execSync`) 대신 인자배열(`execFile`), 프로토타입 오염 방지. *(근거: 5주차)*
- **정적분석/의존성**: SAST(Semgrep/ESLint-security) 를 CI 에 통합하고, `npm audit` 로 의존성 취약점을 관리한다.

## 5. 사고 대응 정책 (11주 연계)

- **절차**: 탐지→분석→봉쇄→근절→복구→교훈 6단계를 따른다. *(근거: 11주차 IR)*
- **증거 보존 우선**: 원본 로그 훼손 금지, 복사·해시로 무결성 고정.
- **연락 체계**: IR 리더/분석가/커뮤니케이션 역할과 에스컬레이션 경로를 사전 정의(플레이북 유지).
- **유출 통지**: 개인정보 유출 시 대상자 통지·비밀번호 강제 변경.

## 6. 인식 제고 정책 (12주 연계)

- **피싱 대응 교육**: 정기 교육 + **모의훈련(격리 환경, 실제 발송 금지)** 을 실시한다. *(근거: 12주차)*
- **신고 문화**: 1-click 신고 버튼 제공, 신고 인센티브, 실패자 후속 교육.
- **MFA/DMARC**: 계정에 MFA 의무화, 송신 도메인 DMARC `p=reject` 적용.
