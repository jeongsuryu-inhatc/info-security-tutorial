# week11 — 초동대응 플레이북 (첫 30분)

> 시나리오: 새벽 관리자 계정으로 대량 주문 취소 발생(11주차 사고).
> 목적: 탐지 직후 30분 내 **증거 보존 + 피해 확산 차단**을 순서대로 수행.

## 1. 초동대응 체크리스트 (순서대로)

- [ ] **1. 사고 선언 & 기록 시작** — 발견 시각·발견자·현상 기록(타임스탬프 명시, KST/UTC 표기).
- [ ] **2. 증거 보존(최우선)** — 로그를 복사·해시(무결성)로 고정. *원본 로그에 쓰기/삭제 금지.*
  ```bash
  mkdir -p ir-evidence && cp starter/incident/*.log ir-evidence/
  shasum -a 256 ir-evidence/*.log > ir-evidence/hashes.txt   # 무결성 증거
  ```
- [ ] **3. 범위 파악** — 공격자 IP·계정·행위 식별(analyze.sh 로 타임라인/IoC 확보).
  ```bash
  bash starter/incident/analyze.sh
  ```
- [ ] **4. 봉쇄** — 공격자 IP(`203.0.113.66`) 차단, **admin 세션 전면 무효화**, `/admin/*` 임시 차단.
- [ ] **5. 계정 잠금** — 침해 계정(`admin@shop.com`) 잠금 + 비밀번호 리셋(연관 계정도 점검).
- [ ] **6. 피해 동결** — DB 백업 스냅샷 확보(롤백 대비), 진행 중 대량 변경 중지.
- [ ] **7. 커뮤니케이션** — 관리자/책임자에게 1차 보고(사실만: 무엇을 언제 확인, 현재 조치).
- [ ] **8. 다음 단계 계획** — 근절(패치)·복구(롤백)·공지 담당과 시한 지정.

## 2. 역할별 첫 30분 액션 (RACI)

| 역할 | 0~10분 | 10~20분 | 20~30분 |
|---|---|---|---|
| **IR 리더** | 사고 선언·타임라인 개시, 우선순위 결정 | 봉쇄 승인(IP 차단·세션 무효화) | 경영/이해관계자 1차 보고 |
| **분석가** | 로그 보존·해시, analyze.sh 실행 | 공격자 IP·계정·행위 확정, IoC 목록화 | 근절 대상(취약점·계정) 식별 |
| **커뮤니케이션** | 내부 알림 채널 개설 | 사실 기반 상황 요약 배포 | 사용자 공지 초안(유출 대상자 대비) |

## 3. 봉쇄 시 주의

- **증거보다 봉쇄가 먼저는 아니다** — 원본 로그를 훼손하지 않도록 복사본을 먼저 확보한 뒤 차단.
- IP 차단·세션 무효화는 **되돌릴 수 있는** 조치부터. 서버 재부팅 등 휘발성 증거를 지우는 조치는 신중히.
- 커뮤니케이션은 **확인된 사실만**. 추정·범인 지목은 보고서(사후)로 미룬다.

## 4. 초동 이후 연결

근절/복구/재발방지는 `ir-report.md` 5·6절 참조 — SQLi 패치(4주),
bcrypt·PII 암호화(7주), 접근통제·HTTPS(8주), IDS 탐지(9주)로 연결한다.
