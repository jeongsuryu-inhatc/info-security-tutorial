# week12 — 피싱 탐지 체크리스트 & 조직 방어책

## 1. 일반 사용자용 피싱 탐지 체크리스트 (10항목)

의심되면 **클릭·입력 전에** 아래를 확인한다. 하나라도 걸리면 신고한다.

- [ ] **1. 발신 주소 정렬** — 표시명은 아는 곳인데 실제 주소/도메인이 다른가? (예: `korea-post.co.kr` 인데 회신은 `...delivery-notice.top`)
- [ ] **2. 링크 실제 목적지** — 링크에 마우스를 올려 **실제 URL**을 본다. 표시 텍스트와 호스트가 다른가? (`portal.univ-mail.ac.kr` 표시 ↔ 실제 `univ--mail.ac.kr-reset.com`)
- [ ] **3. 유사/하이픈/하위도메인 트릭** — `진짜도메인.가짜도메인.top`, `univ--mail...`, `-reset.com` 같은 변형이 있는가?
- [ ] **4. 긴급성/위협** — "24시간 내", "계정 정지", "자정까지" 등 **숙고를 막는 압박**이 있는가?
- [ ] **5. 과도한 이득/희소성** — "선착순", "환급", "당첨" 등 지나치게 좋은 조건인가?
- [ ] **6. 민감정보 요구** — 비밀번호·계좌·신분증·인증번호를 **메일 링크로** 요구하는가? (정상 기관은 안 함)
- [ ] **7. http(평문) 링크** — 로그인 페이지인데 `http://` 인가?
- [ ] **8. 문법/어투 위화감** — 어색한 번역투·오탈자·이상한 서명이 있는가?
- [ ] **9. 예상치 못한 첨부/버튼** — 요청한 적 없는 첨부파일·"지금 확인" 버튼인가?
- [ ] **10. 채널 교차 확인** — 의심되면 **메일 링크 대신** 공식 사이트/전화로 직접 확인했는가?

> 팁: 인증 결과에 `SPF pass`/`DKIM pass` 가 있어도 안심 금물 — **DMARC 정렬 실패**면 사칭이다.

## 2. 조직 차원 방어책

### 2.1 이메일 인증 강화 (송신 도메인)
- **SPF/DKIM/DMARC 모두 게시**하고, DMARC 정책을 `p=none → p=quarantine → p=reject` 로 단계 상향.
- DMARC 리포트(rua) 수집으로 사칭 시도 모니터링.

### 2.2 메일 게이트웨이 (수신)
- 스팸/피싱 필터, **첨부 샌드박싱**, 알려진 악성 도메인 차단(위협 인텔리전스 연동).
- **표시명 사칭 탐지**(내부 임원명 사칭), 외부 발신 메일에 배너 표시(`[외부]`).

### 2.3 링크 보호
- **URL 리라이팅/재검사**(클릭 시점 재평가), 유사도메인·신규등록 도메인 경고.

### 2.4 인증/계정 보호
- **MFA(다단계 인증)** 의무화 — 자격증명이 유출돼도 단독 로그인 차단.
- 비정상 로그인(새 지역/기기) 알림·차단.

### 2.5 사용자 교육/훈련
- 정기 **피싱 모의훈련**(격리 환경, 실제 대상 발송 금지) + 신고 버튼(1-click report) 제공.
- 실패자 대상 후속 교육, 신고자 인센티브로 **신고 문화** 정착.

### 2.6 대응 프로세스
- 신고 접수 → 자동 분류(IoC 추출) → 동일 캠페인 일괄 차단/회수(claw-back).
- 침해 의심 시 계정 잠금·세션 무효화(11주차 IR 연계).

## 3. 우선순위 요약

1순위: **MFA + DMARC `p=reject`** (자격증명 탈취·도메인 사칭의 근본 완화)
2순위: 메일 게이트웨이 + URL 리라이팅 (기술적 차단)
3순위: 모의훈련·신고 문화 (사람 계층 방어)
