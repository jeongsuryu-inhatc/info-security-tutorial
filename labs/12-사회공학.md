# 12주차 실습 — 사회공학

## 1. 학습 목표

- 실제 피싱 메일의 **기술적 단서**(헤더, SPF/DKIM/DMARC, 링크 위장)를 판독할 수 있다.
- 사람을 속이는 **심리 기법**(긴급성·권위·희소성·신뢰)을 사례에서 식별한다.
- 교육용 피싱을 제작해보며 **탐지·방어 체크리스트**를 도출한다.

## ⚠️ 윤리 고지 (필독)
- 이 주차의 피싱 메일 제작은 **교육 목적 산출물**이다.
- **실제 발송·배포는 절대 금지**한다. 수신자는 오직 본인/강의 제출용이다.
- 실제 브랜드 로고·도메인을 사칭하는 산출물을 외부에 공유하지 않는다.

## 2. 사전 준비물

- 강의 제공 실제 피싱 샘플 3건(`.eml` 형식, 헤더 포함, 익명화됨)
- 도구: 이메일 헤더 분석기(수동 또는 MXToolbox 헤더 분석), `dig`(SPF/DMARC 조회)
- 선행 지식: 이메일 동작 원리(SMTP), DNS 기본

## 3. 수업 중 랩 (70분)

> 스타터: `starter/phishing/` (익명화된 교육용 `.eml` 3건 + README)

**Step 0.** 프로젝트 루트에서 제출 폴더를 만든다.
```bash
cd /path/to/workISTutorial
mkdir -p week12
```

### Lab 12-A. 피싱 메일 해부 (45분)

**Step 1.** 각 메일의 인증 결과(SPF/DKIM/DMARC)를 뽑는다.
```bash
cd starter/phishing
grep -Ei "spf=|dkim=|dmarc=" *.eml
```
> 기대: sample1 `spf=fail`, sample2 `dkim=fail/dmarc=fail`, sample3 `spf=pass/dkim=pass`
> 이지만 `dmarc=fail` — **인증 일부 통과라도 DMARC 정렬 실패면 사칭**이라는 핵심 사례.

**Step 2.** `From` vs `Return-Path` / `Reply-To` 불일치를 확인한다.
```bash
grep -Ei "^From:|^Return-Path:|^Reply-To:" *.eml
```

**Step 3.** 실제 발신 서버(Received 체인)와 본문의 위장 링크를 추적한다.
```bash
grep -Ei "^Received:" *.eml
grep -Eio 'href="[^"]+"' *.eml        # 표시 텍스트 vs 실제 URL(유사도메인) 비교
```

**Step 4. (자동화) 세 건을 한 번에 분석해 표의 재료를 만든다.**
아래 스크립트가 인증결과·도메인 정렬·발신서버·링크 위장을 메일별로 정리해 출력한다.
```bash
cd /path/to/workISTutorial
bash starter/phishing/analyze-eml.sh | tee week12/analysis-raw.txt
```
출력 예(sample3 발췌 — 정렬 실패가 드러나는 핵심 케이스):
```
■ sample3-scholarship.eml
  From        : "국가장학재단" <support@univ-scholarship.or.kr>
  Return-Path : <no-reply@scholar-fund-2026.info>
  -- 인증 결과 --   spf=pass  dkim=pass  dmarc=fail (p=none)
  -- 도메인 정렬 --  From=univ-scholarship.or.kr  Return-Path=scholar-fund-2026.info  ⚠️ 불일치
  -- 본문 링크 --   실제 URL: http://scholar-fund-2026.info/apply   표시: 여기를 클릭
```

**Step 5.** 위 출력을 바탕으로 세 건을 표로 정리한다: **발신서버 / SPF·DKIM·DMARC /
From·Return-Path 불일치 / 위장 도메인 / 첨부·링크 위험도**. (샘플별 핵심 단서는 `README.md` 참고)

### Lab 12-B. 심리 기법 태깅 (25분)
각 메일에서 사용된 설득 기법을 분류한다.

| 기법 | 이 메일의 문구 예시 |
|---|---|
| 긴급성 | "24시간 내 미인증 시 계정 정지" |
| 권위 | "보안팀 관리자" 사칭 |
| 희소성 | "선착순 환급" |
| 신뢰 | 실제 로고·서명 도용 |

**랩 제출물**: 3건 분석표(헤더/인증/심리기법).

## 4. 주간 과제 (2.5시간)

### 과제 1. 교육용 피싱 제작 (발송 금지)
가상 서비스 ShopGuard를 사칭하는 **교육용 피싱 메일 1건**을 HTML로 만든다.
`week12/edu-phish.html` 가 **완성 예시**다(그대로 열어보고, 자신의 버전으로 변형).

```bash
# 예시를 브라우저로 열어 구조/태깅을 확인
open week12/edu-phish.html            # (Linux: xdg-open, Windows: start)
```
예시가 지키는 원칙(과제에서도 동일하게):
- **가상 대상만 사칭**(ShopGuard). 실제 브랜드/도메인 사칭 금지.
- **비기능 폼**: `onsubmit`으로 전송 차단 — 실제 자격증명을 수집하지 않는다.
- **조작 기법 태깅**: `[권위]/[긴급성]/[희소성]/[신뢰]` 를 HTML 주석으로 표시.
- **탐지 단서 병기**: `[D1]도메인 불일치 · [D2]링크 위장 · [D4]자격증명 요구` 등을 주석으로 나란히.
- 상단에 **"교육용 예시 — 발송·배포 금지"** 배너를 항상 유지.

> ⚠️ 절대 실제 발송/배포 금지. 산출물은 본인/제출용으로만 사용한다.

### 과제 2. 탐지·방어 체크리스트
- 일반 사용자용 **피싱 탐지 체크리스트**(10항목)를 만든다.
- 조직 차원 방어책(DMARC 정책 강화, 메일 게이트웨이, 사용자 교육, 링크 리라이팅)을 정리한다.

## 7. 흔한 오류 / 확장 과제

**흔한 오류**
- SPF `pass`면 안전하다고 단정 → DMARC 정렬(alignment)과 표시명 사칭은 별개.
- 교육용 산출물을 실제 발송하거나 공유 → **즉시 감점 및 징계 대상**.

**확장 과제 (심화)**
- 오픈소스 프레임워크(GoPhish)를 **로컬 격리 환경에서만** 구성해 캠페인 지표(오픈율·클릭율) 개념을 시연한다(실제 대상 발송 금지).
- 도메인에 DMARC 레코드를 설정하는 실습(테스트 도메인)으로 `p=reject`의 효과를 설명한다.
