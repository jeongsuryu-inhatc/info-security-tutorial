# 11주차 실습 — 침해대응과 디지털 포렌식

## 1. 학습 목표

- 로그·아티팩트를 분석해 **침해 타임라인**을 재구성할 수 있다.
- 침해사고 대응(IR) 절차(탐지→분석→봉쇄→근절→복구→교훈)를 실제 시나리오에 적용한다.
- 근거 기반의 **침해사고 보고서**를 작성할 수 있다.

## 2. 사전 준비물

- 입력 자산: **8주차 `access.log`** + 강의 제공 로그 번들
  (`starter/incident/` — auth.log, web access log, DB 쿼리 로그)
- 도구: `grep`/`awk`/`jq`, 스프레드시트(타임라인 정리), 선택적으로 Timesketch
- 선행 지식: 4·8주차 웹 공격 개념

## 3. 수업 중 랩 (80분)

### 시나리오
> ShopGuard 관리자가 "새벽에 관리자 계정으로 대량 주문 취소가 발생했다"고 신고했다.
> 제공된 로그로 무슨 일이 일어났는지 규명하라.

> 스타터: `starter/incident/` (web-access.log, auth.log, db-query.log)

**Step 0.** 프로젝트 루트에서 제출 폴더를 만든다.
```bash
cd /path/to/workISTutorial
mkdir -p week11
```

### Lab 11-A. 흔적 수집 (30분)

**Step 1.** 웹 로그에서 비정상 요청을 추출한다.
```bash
cd starter/incident
grep -Ei "sqlmap|union select|or 1=1|sleep\(|'--" web-access.log   # 공격 도구·SQLi
grep -E '" (401|500) ' web-access.log                             # 실패 응답
```
> 기대: `203.0.113.66` 이 `sqlmap/1.7` UA 로 `' AND 1=1--`, `' OR SLEEP(3)--`,
> `' UNION SELECT ...`, `admin@shop.com'--` 를 순차 시도. 마지막 `'--` 요청이 **200**(우회 성공).

**Step 2.** 인증 로그에서 우회 성공 로그인과 출발 IP를 찾는다.
```bash
grep -Ei "LOGIN SUCCESS|bypass|ADMIN ACTION|SESSION" auth.log
```
> 기대: `03:13:44 LOGIN SUCCESS user=admin@shop.com src=203.0.113.66 note="password check bypassed"`
> 이후 `ADMIN ACTION cancel-all-orders`, `ADMIN ACTION export table=users`.

**Step 3.** DB 로그에서 권한 밖 쿼리(WHERE 없는 대량 UPDATE 등)를 찾는다.
```bash
grep -Ei "UPDATE|DELETE|SELECT email,password|SELECT \*" db-query.log
```
> 기대: `UPDATE orders SET total=0, product='CANCELLED'` (**WHERE 절 없음** → 전체 주문 조작),
> `SELECT email,password,phone FROM users` (자격증명·PII 탈취).

**Step 4.** 공격자 IP로 전체 로그를 교차 검색해 활동을 묶는다.
```bash
grep -rn "203.0.113.66" .
```

**Step 5. (자동화) 흔적 수집 + 타임라인 생성을 한 번에 수행한다.**
위 Step 1~4 를 자동으로 실행하고, 3개 로그의 시각을 ISO8601 로 정규화해 병합·정렬한
타임라인 CSV(`week11/timeline.csv`)를 만든다.
```bash
cd /path/to/workISTutorial
bash starter/incident/analyze.sh          # 화면: IoC/단계별 흔적 + week11/timeline.csv 생성
column -s, -t week11/timeline.csv | head -30   # 표로 보기
```

### Lab 11-B. 타임라인 재구성 (50분)
`analyze.sh` 가 만든 `week11/timeline.csv` 를 검토하고, 각 이벤트의 **해석**을 덧붙여
공격 흐름을 서술한다. 실제 생성되는 타임라인(발췌):

| 시각(KST) | 소스 | 이벤트 | 해석 |
|---|---|---|---|
| 03:10~11 | auth | `Failed password for invalid user admin` (203.0.113.66) | SSH 무차별 대입(정찰) |
| 03:11 | web | `sqlmap` 으로 `' AND 1=1--`/`UNION SELECT` 반복 | SQLi 인증 우회 시도 |
| 03:13:44 | web/auth | `admin@shop.com'--` → **200**, `LOGIN SUCCESS ... bypassed` | 인증 우회 성공(침투) |
| 03:14 | auth/db | `SESSION admin`, `SELECT * FROM orders` | 권한 확보·정찰 |
| 03:15:31 | db | `UPDATE orders SET total=0 ...` (WHERE 없음) | 대량 주문 조작(목적 달성) |
| 03:16:11 | db | `SELECT email,password,phone FROM users` | 자격증명·PII 탈취 |

**랩 제출물**: `week11/timeline.csv` + 최소 5개 이벤트에 대한 해석 표.

## 4. 주간 과제 (3시간)

### 과제 1. 침해사고 보고서(IR Report)

**Step 1-1. 근거 자료(타임라인·IoC)를 준비한다.**
```bash
# 타임라인 CSV 생성(Lab 11-A Step 5 와 동일)
bash starter/incident/analyze.sh

# IoC 후보를 한 번에 뽑아 보고서 3장에 붙여넣기
cd starter/incident
echo "== 공격자 IP =="; grep -oE "203\.0\.113\.66" web-access.log | sort -u
echo "== 공격 도구(UA) =="; grep -oiE "sqlmap/[0-9.]+" web-access.log | sort -u
echo "== SQLi 페이로드 =="; grep -oiE "'[^\"]*(--|OR|UNION|SLEEP)[^\"]*" web-access.log | sort -u
echo "== 침해 계정 =="; grep -oiE "user=[^ ]+|by=[^ ]+" auth.log | sort -u
echo "== 탈취 대상 =="; grep -iE "export|SELECT email,password|UPDATE orders" ../incident/db-query.log
cd ../..
```

**Step 1-2. 아래 목차로 보고서(`week11/ir-report.md`)를 작성한다.** 각 항목은 위에서 뽑은
근거 로그 라인을 **직접 인용**한다.
1. **개요** — 무엇이, 언제, 어떻게 (예: 2026-08-14 03:13~03:16, SQLi 인증우회로 admin 탈취)
2. **타임라인** — `timeline.csv` 기반, 근거 로그 라인 인용 포함
3. **침해 지표(IoC)** — IP(`203.0.113.66`), 계정(`admin@shop.com`), 페이로드(`admin@shop.com'--`), 도구(`sqlmap/1.7`)
4. **영향 범위** — 전체 주문 조작(`UPDATE orders ... WHERE 없음`), users 테이블 자격증명/PII 탈취
5. **대응 조치** — 봉쇄(해당 IP 차단·admin 세션 무효화)/근절(비번 리셋·SQLi 패치)/복구(주문 데이터 롤백)
6. **재발 방지** — 4주차 Prepared Statement, 8주차 접근통제/HTTPS 와 연결

## 7. 흔한 오류 / 확장 과제

**흔한 오류**
- 로그 시간대(UTC vs KST) 혼동으로 타임라인 왜곡 → 타임존 명시·정규화.
- 추정과 사실을 섞음 → 근거 로그 라인을 반드시 인용.

**확장 과제 (심화)**
- 메모리 덤프(강의 제공)에서 Volatility로 악성 프로세스를 식별한다.
- 삭제된 파일 복구(파일 카빙, `foremost`)를 시연한다.
