# 2주차 실습 — 시스템보안

## 1. 학습 목표

- 리눅스 시스템 하드닝의 핵심 원칙(최소 권한, 공격 표면 축소)을 실습으로 체득한다.
- 사용자 권한·서비스·SSH 접근을 안전하게 재구성할 수 있다.
- 하드닝 전후를 **정량 지표(Lynis 점수)**로 비교·검증할 수 있다.

## 2. 사전 준비물

- Docker Desktop 또는 VirtualBox
- 스타터 자산: `starter/shopguard-web.Dockerfile` (의도적으로 느슨하게 설정된 Ubuntu 기반 웹서버 이미지)
- 도구: [Lynis](https://cisofy.com/lynis/) (감사 스캐너)
- 선행 지식: 리눅스 기본 명령어, `chmod`/`chown`, 텍스트 에디터(vim/nano)

## 3. 수업 중 랩 (70분)

의도적으로 취약하게 설정된 ShopGuard 웹서버 컨테이너를 단계별로 하드닝한다.
아래 명령을 **순서대로** 실행한다. `[호스트]`는 노트북 터미널, `[컨테이너]`는
컨테이너 셸 안에서 실행한다는 뜻이다.

> 스타터 파일: `starter/shopguard-web.Dockerfile` (이 저장소에 포함됨)

**Step 0.** `[호스트]` 프로젝트 루트에서 제출 폴더를 만든다(모든 결과물을 여기에 저장).
```bash
cd /path/to/workISTutorial   # 저장소 루트로 이동
mkdir -p week02
```

### Lab 2-A. 이미지 빌드 · 컨테이너 진입 (10분)

**Step 1.** `[호스트]` 프로젝트 루트에서 이미지를 빌드한다.
```bash
cd /path/to/workISTutorial
docker build -t shopguard-web -f starter/shopguard-web.Dockerfile .
```

**Step 2.** `[호스트]` 컨테이너를 대화형으로 실행해 셸로 진입한다.
```bash
docker run -it --name sg-web shopguard-web
# 이후 프롬프트가 root@<id>:/# 로 바뀌면 컨테이너 내부다.
```

### Lab 2-B. 기준선(Before) 측정 (15분)

**Step 3.** `[컨테이너]` 취약 서비스를 일부러 기동해 "하드닝 전" 상태를 만든다.
```bash
service ssh start          # SSH (22) - root 로그인/비번 인증 허용 상태
service vsftpd start       # FTP (21) - 평문 전송
service openbsd-inetd start  # telnet (23) 등 inetd 서비스
```

**Step 4.** `[컨테이너]` 실행 중 서비스와 열린 포트를 기록한다.
```bash
service --status-all         # 서비스 목록 (+가 실행 중)
ss -tlnp                     # LISTEN 중인 포트 확인 (21,22,23,3000 보여야 함)
```

**Step 5.** `[컨테이너]` Lynis 기준선 스캔을 실행하고 **하드닝 지수**를 기록한다.
```bash
lynis audit system --quick 2>&1 | tee /tmp/lynis-before.txt
grep -i "Hardening index" /tmp/lynis-before.txt   # 예: Hardening index : 56 [######......]
```
> 이 점수를 스크린샷으로 남긴다 (= Before).

### Lab 2-C. 하드닝 (35분)

**Step 6.** 평문·불필요 서비스 중지 후 제거한다.
```bash
service vsftpd stop
service openbsd-inetd stop
apt-get remove --purge -y vsftpd inetutils-telnetd openbsd-inetd telnet
```

**Step 7.** world-writable 파일/디렉터리를 찾아 권한을 조인다.
```bash
find / -xdev -type f -perm -0002 2>/dev/null      # world-writable 파일 탐지
find / -xdev -type d -perm -0002 2>/dev/null      # world-writable 디렉터리 탐지
chmod 0750 /var/www/shopguard
chmod 0640 /var/www/shopguard/config.env
ls -l /var/www/shopguard                          # 권한이 좁혀졌는지 확인
```

**Step 8.** 웹 프로세스를 root가 아닌 `appuser`로 실행한다.
```bash
# (Before) root로 실행되던 방식 - 확인만
#   node /var/www/shopguard/server.js
chown -R appuser:appuser /var/www/shopguard
runuser -u appuser -- node /var/www/shopguard/server.js &
curl -s localhost:3000        # 응답: "ShopGuard OK - running as appuser"
```

**Step 9.** `appuser`의 무제한 sudo를 최소 권한으로 교체한다.
```bash
cat /etc/sudoers.d/99-appuser        # (Before) appuser ALL=(ALL) NOPASSWD:ALL
# 서비스 재시작 명령만 허용하도록 축소
echo 'appuser ALL=(root) /usr/sbin/service *' > /etc/sudoers.d/99-appuser
chmod 0440 /etc/sudoers.d/99-appuser
visudo -c                            # 문법 검증: "parsed OK" 확인
```

**Step 10.** SSH를 강화한다 (root 로그인·비밀번호 인증 차단).
```bash
sed -i 's/^PermitRootLogin.*/PermitRootLogin no/'            /etc/ssh/sshd_config
sed -i 's/^PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
grep -E 'PermitRootLogin|PasswordAuthentication' /etc/ssh/sshd_config
service ssh restart
```

**Step 11.** 앱 계정의 약한 비밀번호와 비밀번호 정책을 손본다.
```bash
passwd -l root                       # root 비밀번호 로그인 잠금
# appuser 비밀번호를 강한 값으로 변경 (예시)
echo 'appuser:S3cure-Pass!2026' | chpasswd
```

### Lab 2-D. 재측정(After) (10분)

**Step 12.** `[컨테이너]` Lynis를 다시 실행해 점수 변화를 확인한다.
```bash
lynis audit system --quick 2>&1 | tee /tmp/lynis-after.txt
grep -i "Hardening index" /tmp/lynis-after.txt    # Before보다 상승했는지 확인
```

**Step 13.** `[호스트]` Before/After 결과 파일을 제출 폴더로 복사한다.
```bash
docker cp sg-web:/tmp/lynis-before.txt ./week02/lynis-before.txt
docker cp sg-web:/tmp/lynis-after.txt  ./week02/lynis-after.txt
```

**Step 14.** (정리) 실습 종료 후 컨테이너를 제거한다.
```bash
exit                          # 컨테이너 셸 빠져나오기
docker rm -f sg-web           # [호스트]
```

**랩 제출물**: Step 5(Before)·Step 12(After)의 하드닝 지수 스크린샷 2장.

> ℹ️ 컨테이너에는 systemd가 없어 `systemctl` 대신 `service`(SysV) 명령을 쓴다.
> 완전한 systemd 환경으로 실습하려면 VirtualBox에 Ubuntu Server를 설치하고
> Step 3~12를 `systemctl`/`sudo`로 동일하게 수행하면 된다.

## 7. 흔한 오류 / 확장 과제

**흔한 오류**
- SSH `PasswordAuthentication no`로 바꾼 뒤 키 등록을 안 해 접속 불가 → 반드시 새 세션으로 접속 테스트 후 기존 세션 종료.
- 서비스를 stop만 하고 disable 안 함 → 재부팅 시 부활.

**확장 과제 (심화)**
- CIS Benchmark 항목 5개를 추가로 적용하고 근거를 인용한다.
- 하드닝 절차를 **Bash 스크립트로 자동화**하여 새 컨테이너에 1회 실행으로 재현되게 만든다.
