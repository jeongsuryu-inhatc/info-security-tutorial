# 6주차 실습 — 악성코드

## 1. 학습 목표

- 악성코드를 **격리 환경에서 안전하게 다루는 절차**를 익힌다.
- 정적 분석(문자열·해시·메타데이터)으로 파일의 악성 징후를 판별할 수 있다.
- **시그니처 기반 탐지기**를 직접 구현해 탐지 원리와 한계를 이해한다.

## 2. 사전 준비물

- **격리 실행 환경** (아래 둘 중 하나)
  - (권장) **Docker** — `starter/malware-lab/`의 네트워크 격리 컨테이너. VM 없이 가볍게 격리.
  - (대안) **네트워크가 차단된 VM**(VirtualBox, Host-only 어댑터).
- 샘플: EICAR 테스트 파일, 강의 제공 공개 샘플 해시 세트 (`starter/sample-hashes.json`)
- 도구: `sha256sum`, `strings`, `file`, [VirusTotal](https://virustotal.com)(해시 조회만),
  Node.js 20
- 선행 지식: 해시 함수 개념

> **왜 이 랩은 Docker로 충분한가?** 이 랩은 실제 악성코드를 **실행하지 않는다.**
> EICAR(무해한 표준 테스트 파일)과 정적 분석(문자열·해시·메타데이터), 시그니처
> 스캐너 구현이 전부다. 따라서 "코드 실행 없는 분석"에는 컨테이너 격리로 충분하다.
> **단, 진짜 라이브 멀웨어를 실제로 실행(detonate)** 하려면 커널을 공유하는 Docker로는
> 부족하며 **반드시 네트워크 격리 VM**을 써야 한다.

## ⚠️ 안전 수칙 (필독)
- 실제 악성 샘플은 **격리 환경(격리 컨테이너 또는 VM) 안에서만** 열고, 실습 후
  **컨테이너/스냅샷을 폐기**한다.
- 호스트 OS로 샘플을 복사하거나 실행하지 않는다.
- 격리 환경은 **네트워크를 차단**한다(Docker: `--network none` / VM: Host-only).
  샘플이 외부로 비컨하거나 추가 페이로드를 내려받지 못하게 한다.
- VirusTotal에는 **파일이 아니라 해시만** 업로드한다(민감 파일 유출 방지).

### Docker 격리 환경 준비 (VM 대체)
```bash
# 이미지 빌드 (file/strings/sha256sum + Node.js 20, 비특권 사용자)
docker compose -f starter/malware-lab/docker-compose.yml build

# 네트워크가 완전히 차단된(network_mode: none) 격리 셸 진입.
# week06/ 가 컨테이너의 /work 로 마운트되므로, 호스트에서 편집하고 안에서 실행한다.
docker compose -f starter/malware-lab/docker-compose.yml run --rm lab

# (셸 없이) 스캐너만 일회성 실행:
docker compose -f starter/malware-lab/docker-compose.yml run --rm lab \
  node scanner.js ./test-folder
```
> 격리 검증: 컨테이너 안에서 `getent hosts example.com` 이 실패하면(네트워크 없음)
> 격리가 정상 동작하는 것이다. 자세한 격리 설정은 `starter/malware-lab/README.md` 참고.

### Lab 6-A. EICAR 정적 분석 (25분)

**Step 1. EICAR 표준 테스트 파일을 만든다.**
EICAR는 백신 동작 확인용 **무해한** 표준 문자열이다(실제 악성코드 아님). 호스트 백신이
실시간 검사 중이면 이 파일을 지울 수 있으니, 반드시 격리 환경 안에서 만든다.
```bash
printf '%s' 'X5O!P%@AP[4\PZX54(P^)7CC)7}$EICAR-STANDARD-ANTIVIRUS-TEST-FILE!$H+H*' > /work/eicar.com
```

**Step 2. 메타데이터·문자열·해시를 추출한다.** 정적 분석 3종 세트다.
```bash
file /work/eicar.com          # 파일 타입 추정 → "DOS/MBR boot sector" 등으로 나옴
strings /work/eicar.com       # 사람이 읽을 수 있는 문자열 → EICAR 시그니처 원문이 보임
sha256sum /work/eicar.com     # 콘텐츠 지문(해시)
```
기대 결과(핵심): SHA-256이 아래와 정확히 일치해야 한다. `rules.json`의 블랙리스트와 같은 값이다.
```
275a021bbfb6489e54d471899f7db9d1663fc695ec2fe2a2c4538aabf651fd0f  /work/eicar.com
```
> 해석 포인트: 파일 **내용이 1바이트라도 바뀌면 해시가 완전히 달라진다.** 시그니처(해시)
> 탐지가 변종에 약한 이유가 바로 이것이다(과제 4의 우회 시연으로 이어짐).

**Step 3. VirusTotal에서 해시로 조회한다(파일 업로드 금지).**
`https://www.virustotal.com` → **Search** 탭 → Step 2의 SHA-256 값을 붙여넣기 → 조회.
```
275a021bbfb6489e54d471899f7db9d1663fc695ec2fe2a2c4538aabf651fd0f
```
여러 백신이 `EICAR-Test-File` 계열 이름으로 탐지한 결과가 나온다. **탐지명 몇 개를 캡처**한다.
> 왜 해시만? 실제 민감/악성 파일을 업로드하면 외부로 유출된다. **해시 조회는 파일을
> 노출하지 않고** 이미 알려진 샘플인지 확인하는 안전한 방법이다.

### Lab 6-B. 공개 샘플 판독 (35분)

Step 0에서 복사한 `week06/samples/`의 샘플 3종을 정적 분석한다.
셋 다 **실제 악성이 아니라**, 전형적 악성 패턴(문자열)을 담은 학습용 텍스트다.
- `sample_A` — 원격 페이로드 다운로드 후 즉시 실행(`curl … | sh`) 드로퍼
- `sample_B` — `eval(atob(...))` 난독화 JS + 대용량 Base64 블롭
- `sample_C` — 인코딩된 PowerShell(`powershell -enc`) + 레지스트리 자동실행 등록

**Step 4. 각 샘플에서 의심 지표(IoC 후보)를 추출한다.**
```bash
cd /work/samples

# (a) 문자열에서 URL·실행파일·경로·레지스트리 키 등 의심 지표만 필터링
for f in sample_A sample_B sample_C; do
  echo "===== $f ====="
  strings -n 6 "$f" | grep -Ei 'https?://|\.exe|powershell|cmd|/tmp|HKEY|\| *sh|\| *bash'
done

# (b) 각 샘플의 콘텐츠 지문(해시) 확보 — IoC 목록·VirusTotal 조회에 사용
sha256sum sample_A sample_B sample_C
```
기대 결과(예): `sample_A`에서 `http://malicious-cdn.example.net/...`, `http://185.203.116.44/install`,
`/tmp/.cache-update` 등이, `sample_C`에서 `powershell.exe -enc ...`, `HKEY_CURRENT_USER\...\Run`,
`http://update-service.example.com/...` 등이 추출된다.

**Step 5. 시그니처 스캐너로 자동 판정과 대조한다(선택, 과제 예열).**
Step 0에서 이미 `scanner.js`·`rules.json`을 `/work`에 복사해 뒀다. 폴더 전체를 스캔해
사람이 뽑은 IoC와 룰 기반 자동 탐지를 비교한다.
```bash
node /work/scanner.js /work/samples /work/rules.json
```
기대 출력(요약):
```
스캔 대상: /work/samples  (파일 3개, 탐지 4건)
[HIGH] .../sample_A  (string:wget-pipe-sh) — 다운로드 후 즉시 실행
[HIGH] .../sample_B  (string:js-eval-atob) — 난독화된 JS 페이로드
[HIGH] .../sample_C  (string:ps-encoded)   — 인코딩된 PowerShell 실행
[LOW]  .../sample_B  (string:base64-blob)  — 대용량 Base64 블롭(오탐 주의)
```

**Step 6. IoC(침해지표) 목록을 표로 정리한다.**
Step 4~5에서 얻은 URL·IP·경로·레지스트리 키·해시를 유형별로 목록화한다. 예:

| 유형 | 값 | 출처 샘플 |
|---|---|---|
| URL | `http://malicious-cdn.example.net/payload/stage2.sh` | sample_A |
| IP | `185.203.116.44` | sample_A |
| 경로 | `/tmp/.cache-update` | sample_A |
| 레지스트리 | `HKCU\...\CurrentVersion\Run\Updater` | sample_C |
| SHA-256 | `b6bd6d1e…`(sample_A) 등 | 전체 |

> 이 IoC 목록은 **13주차 위험평가**에서 재사용한다.

**랩 제출물**: Step 2 EICAR 해시·문자열 + Step 3 VirusTotal 탐지명 캡처 +
Step 4 샘플별 의심 문자열 + Step 6 IoC 표.

## 4. 주간 과제 (2.5시간)

### 과제. Node.js 시그니처 스캐너 구현
룰셋을 제출 폴더로 복사하고, 그 옆에 `scanner.js`를 만든다. `starter/malware-lab/scanner.example.js`
가 **참고 구현**이므로(그대로 베끼지 말고 구조를 참고), 필요하면 복사해서 시작한다.
```bash
mkdir -p week06
cp starter/sample-hashes.json         week06/rules.json          # 스캐너가 참조할 룰셋
cp starter/malware-lab/scanner.example.js week06/scanner.js       # 참고 구현(직접 수정)
```
`week06/rules.json`의 악성 해시·문자열 룰을 활용해 스캐너를 만든다.

요구 기능:
1. **해시 매칭**: 지정 폴더 내 모든 파일의 SHA-256을 계산해 블랙리스트와 대조.
2. **문자열 룰**: 정규식 기반 의심 문자열(예: `eval\\(atob`, `powershell -enc`) 탐지.
3. **리포트**: 탐지 파일명·매칭 룰·심각도를 JSON/표로 출력.
4. 탐지 스캐너를 **테스트 폴더(정상 파일 + EICAR)**에 돌려 정탐/오탐을 평가.

#### 구현 뼈대 (핵심 3요소)

**(1) 스트리밍 SHA-256** — 대용량 파일을 통째로 메모리에 올리지 않는다(흔한 오류).
```js
const crypto = require('crypto');
const fs = require('fs');
function sha256Stream(file) {
  return new Promise((resolve, reject) => {
    const hash = crypto.createHash('sha256');
    fs.createReadStream(file)
      .on('error', reject)
      .on('data', (chunk) => hash.update(chunk))
      .on('end', () => resolve(hash.digest('hex')));
  });
}
```

**(2) 정규식 문자열 룰** — `rules.json`의 `strings[]`를 미리 컴파일해 대조.
```js
const rules = JSON.parse(fs.readFileSync('rules.json', 'utf8'));
const stringRules = rules.strings.map((r) => ({ ...r, regex: new RegExp(r.pattern, 'i') }));
// 파일 내용(바이트 보존: 'latin1')에 대해 regex.test(content) 로 매칭.
// 대용량 바이너리는 상한(예: 5MB)까지만 읽어 오탐·부담을 줄인다.
```

**(3) 심각도 정렬 리포트** — 표 + JSON 동시 출력, 탐지 시 종료코드 1(CI 연동).
```js
report.sort((a, b) => ({high:0,medium:1,low:2}[a.severity] - {high:0,medium:1,low:2}[b.severity]));
process.exit(report.length > 0 ? 1 : 0);
```

테스트 폴더 준비(정탐/오탐 평가용):
```bash
mkdir -p week06/test-folder
printf '%s' 'X5O!P%@AP[4\PZX54(P^)7CC)7}$EICAR-STANDARD-ANTIVIRUS-TEST-FILE!$H+H*' > week06/test-folder/eicar.com
echo 'eval(atob("YWxlcnQoMSk="))' > week06/test-folder/suspicious.js   # 문자열 룰 정탐 대상
echo '평범한 정상 파일' > week06/test-folder/clean.txt                 # 오탐 나면 안 됨
```
실행 예(Docker 격리 컨테이너 안 또는 호스트에서):
```
node scanner.js ./test-folder
#
# 스캔 대상: ./test-folder  (파일 3개, 탐지 2건)
# [HIGH] .../eicar.com      (hash:EICAR-Test-File) — sha256=275a021b...fd0f
# [HIGH] .../suspicious.js  (string:js-eval-atob)  — 난독화된 JS 페이로드
#   → clean.txt 는 탐지 안 됨(정상)
```

#### 시그니처 우회 시연 (확장 과제 연계, 권장)
Base64로 EICAR를 감싸면 원본 해시와 문자열 룰을 **둘 다 회피**함을 보인다.
```bash
# EICAR를 Base64로 '패킹' → 해시가 달라지고 EICAR 원문 문자열도 사라짐
# (stdin 리다이렉트 형태는 GNU/coreutils·macOS 양쪽에서 동일하게 동작)
base64 < week06/test-folder/eicar.com > week06/test-folder/eicar.packed.b64
node scanner.js ./test-folder     # eicar.packed.b64 는 미탐(hash·string 모두 회피)
```
이후 스캐너에 **디코딩 단계**(base64 후보를 디코드해 재검사)를 추가하면 다시 탐지된다.
이 미탐 → 재탐지 과정을 보고서의 "시그니처 한계" 근거로 사용한다.

**보고서**: 시그니처 방식의 한계(변종·패킹·제로데이 미탐)를 위 우회 시연으로
뒷받침하고, 행위 기반/휴리스틱 탐지와 비교한다.

## 7. 흔한 오류 / 확장 과제

**흔한 오류**
- 대용량 파일을 통째로 메모리에 읽어 스캔 → 스트리밍 해시(`crypto.createHash` + stream) 사용.
- 안전 수칙 미준수(호스트에서 샘플 오픈) → **감점 및 재제출**.

**확장 과제 (심화)**
- YARA 룰 문법을 학습해 문자열 룰을 YARA 형식으로 재작성한다.
- 간단한 패커(Base64 인코딩)로 EICAR를 감싼 뒤, 시그니처 스캐너가 미탐하는 것을 시연하고 디코딩 단계를 추가해 재탐지한다(과제 4 "시그니처 우회 시연" 참고).
