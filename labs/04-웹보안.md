- OWASP Top 10 중 인젝션·XSS의 동작 원리를 직접 공격으로 이해한다.

**Step 5.** 취약 코드(`auth.js`)의 문자열 결합 부분을 눈으로 확인한다.
```js
const sql = `SELECT id, email, role FROM users
             WHERE email = '${email}' AND password = '${password}'`;
```

**Step 6.** SQLi로 비밀번호 검사를 우회해 **관리자로 로그인**한다(터미널에서 재현).
`email` 칸 끝에 `--`를 붙여 뒤따르는 `AND password = '...'` 조건을 통째로 주석 처리한다.
```bash
curl -s -X POST localhost:3000/login \
  --data-urlencode "email=admin@shop.com'--" \
  --data-urlencode "password=아무거나"
# 기대 응답: {"ok":true,"user":{"id":1,"email":"admin@shop.com","role":"admin"}}
#   생성되는 SQL: ... WHERE email = 'admin@shop.com'--' AND password = '아무거나'
#   → '--' 이후가 주석 처리되어 password 검사가 사라짐 → admin 행 반환
```

**Step 7.** 정상 로그인과 비교해 우회가 성립한 이유를 설명한다.
```bash
curl -s -X POST localhost:3000/login \
  --data-urlencode "email=admin@shop.com" --data-urlencode "password=wrong"
# 기대 응답: 401 인증 실패  ← 정상 동작
```

**랩 제출물**: Juice Shop 2개 챌린지 캡처 + Step 6 인증 우회 성공 캡처.

## 4. 주간 과제 (3시간)

### 과제 1. SQLi PoC 문서화
- ShopGuard 로그인에서 성공한 **3가지 이상의 SQLi 페이로드**와 각각의 원리를 정리한다.
  (인증 우회, UNION 기반 데이터 추출, 오류 기반 정보 노출 등)
- 각 페이로드마다 (a) 입력값 (b) 생성되는 SQL (c) 실제 응답 (d) 원리를 남긴다.
- 참고: SQLite는 MySQL식 `extractvalue()/updatexml()` 같은 **에러에 값을 실어 빼내는
  기법이 없다.** "오류 기반"은 컬럼 수·컬럼/테이블명 등 **구조 정보 노출**로 접근하고,
  실제 값 추출은 UNION 또는 블라인드(부울)로 피벗한다.
- 작성 예시는 `week04/exploits.md` 참고(인증 우회 3종 · UNION 4종 · 오류 기반 3종 · 블라인드 보너스).

### 과제 2. 취약 → 안전 리팩터링
- `starter/shopguard-app/auth.js`를 **직접 수정**해 Prepared Statement(파라미터 바인딩)로 바꾼다.

```js
// 안전 버전 (값은 항상 ? 로 바인딩)
const row = db.prepare(
  'SELECT id, email, role, password FROM users WHERE email = ?'
).get(email);
if (!row || row.password !== password) return null;
return { id: row.id, email: row.email, role: row.role };
```

- 추가로 **입력 검증(이메일 형식)**과 **응답 헤더 CSP**를 적용해 XSS를 완화한다.
- 리팩터링 후 과제 1의 모든 페이로드가 **차단됨을 재현**한다.
  ```bash
  # 서버 재시작 후: 우회 시도 → 이제 401 이어야 정상
  curl -s -X POST localhost:3000/login \
    --data-urlencode "email=admin@shop.com'--" --data-urlencode "password=x"
  # UNION 추출 시도도 차단되어야 함
  curl -s -X POST localhost:3000/login \
    --data-urlencode "email=' UNION SELECT id, email, password FROM users--" --data-urlencode "password=x"
  # 정상 로그인은 여전히 성공
  curl -s -X POST localhost:3000/login \
    --data-urlencode "email=alice@shop.com" --data-urlencode "password=alice1234"
  ```
- 제출용으로 복사한다.
  ```bash
  cp starter/shopguard-app/auth.js week04/auth.js
  ```

## 7. 흔한 오류 / 확장 과제

**흔한 오류**
- Prepared Statement를 쓰면서 여전히 문자열 결합으로 `LIKE '%'+q+'%'` 만드는 실수 → 값은 항상 바인딩.
- 비밀번호를 평문 비교. 이번 주는 우회 개념에 집중하되, **7주차에서 bcrypt로 이관**됨을 명시.

**확장 과제 (심화)**
- **2차(stored) XSS**를 상품 리뷰 기능에서 재현하고, 출력 인코딩으로 방어한다.
- ORM(예: better-sqlite3 대신 Prisma) 도입이 인젝션 방어에 주는 이점과 한계를 비교한다.
