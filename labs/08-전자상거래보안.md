### Lab 8-B. HTTPS 전환 (30분)

**Step 5.** 개발용 자체 서명 인증서를 발급한다(앱 폴더 안에서). 개인키 `ssl.key`,
인증서 `ssl.crt` 가 생성된다.
```bash
cd starter/shopguard-app
openssl req -x509 -newkey rsa:2048 -nodes \
  -keyout ssl.key -out ssl.crt -days 365 -subj "/CN=localhost"
ls ssl.key ssl.crt                  # 두 파일 생성 확인
```
> mkcert를 쓰면 브라우저 신뢰 인증서를 만들 수 있지만(`mkcert localhost`), 이 랩은
> `curl -k`(인증서 검증 생략)로 헤더만 확인하므로 openssl 자체 서명으로 충분하다.
> 어느 방식이든 **파일명을 `ssl.key`/`ssl.crt` 로 맞추면** 아래 `server-secure.js` 가 그대로 읽는다.

**Step 6.** `server.js`를 복제해 `server-secure.js`를 만들고 HTTPS + helmet을 적용한다.
`helmet()`으로 보안 헤더를 일괄 적용하고, Step 5의 `ssl.key`/`ssl.crt`로 HTTPS(3443)를 연다.
전체 코드는 `week08/server-secure.js` 참고(그대로 복사해 `starter/shopguard-app/server-secure.js` 로 사용).
```js
const express = require('express');
const https = require('https'), fs = require('fs'), path = require('path');
const helmet = require('helmet');
const app = express();

app.use(helmet());                              // 보안 헤더 일괄 적용
// ... (로그/로그인/주문 라우터 마운트는 server.js 와 동일) ...

https.createServer({
  key:  fs.readFileSync(path.join(__dirname, 'ssl.key')),   // Step 5의 개인키
  cert: fs.readFileSync(path.join(__dirname, 'ssl.crt')),   // Step 5의 인증서
}, app).listen(3443, () => console.log('https://localhost:3443'));
```
```bash
# 실행 (helmet 설치 후)
npm install helmet
npm run seed && node server-secure.js          # https://localhost:3443
```

**Step 7.** 보안 헤더가 실렸는지 확인한다(자체 서명이므로 `-k`로 인증서 검증 생략).
```bash
curl -skI https://localhost:3443/ | grep -Ei 'strict-transport|x-frame|x-content|content-security'
# 기대: Strict-Transport-Security / X-Frame-Options / X-Content-Type-Options / Content-Security-Policy 노출
```

**랩 제출물**: Step 2/3 IDOR·가격조작 성공 캡처 + Step 7 보안 헤더 응답 캡처.

## 4. 주간 과제 (3시간)

### 과제 1. 취약점 수정
`starter/shopguard-app/routes/orders.js`를 **직접 수정**한다. 전체 수정본은
`week08/orders.js` 참고.

**IDOR 방어** — 주문 조회 시 요청자(`x-user-id`)와 주문 `user_id`를 대조하고, 내 주문이
아니면 404(존재 자체를 숨겨 열거 방지).
```js
router.get('/orders/:id', (req, res) => {
  const db = openDb();
  try {
    const order = db.prepare('SELECT * FROM orders WHERE id = ?').get(req.params.id);
    if (!order || order.user_id !== currentUserId(req)) {   // ✅ 소유자 검증
      return res.status(404).json({ error: 'not found' });
    }
    res.json(order);
  } finally { db.close(); }
});
```

**가격 조작 방어** — 클라이언트가 보낸 `total`을 **무시**하고, 서버가 products 테이블
가격으로 총액을 재계산한다(가격의 출처는 항상 서버 DB).
```js
router.post('/orders', express.json(), (req, res) => {
  const { product } = req.body;
  const quantity = Math.trunc(Number(req.body.quantity ?? 1));
  if (typeof product !== 'string' || !product.trim())
    return res.status(400).json({ error: 'product 필드가 필요합니다.' });
  if (!Number.isInteger(quantity) || quantity < 1)
    return res.status(400).json({ error: 'quantity 는 1 이상의 정수여야 합니다.' });

  const db = openDb();
  try {
    const row = db.prepare('SELECT price FROM products WHERE name = ?').get(product);
    if (!row) return res.status(400).json({ error: '존재하지 않는 상품입니다.' });
    const total = row.price * quantity;                     // ✅ 서버가 재계산
    const info = db.prepare(
      'INSERT INTO orders (user_id, product, total, created) VALUES (?, ?, ?, ?)'
    ).run(currentUserId(req), product, total, new Date('2026-08-15T00:00:00Z').toISOString());
    res.status(201).json({ id: info.lastInsertRowid, product, quantity, total });
  } finally { db.close(); }
});
```

**배치 & 재현** — 수정본을 앱에 넣고 서버를 재기동한 뒤, 랩의 공격이 모두 차단됨을 확인한다.
```bash

cp ../../week08/server-secure.js .                     # HTTPS+helmet 서버

```
다른 터미널에서(자체 서명이라 `-k`):
```bash
# IDOR 차단: alice(2)가 bob의 주문(id=2) 조회 → 404
curl -sk -o /dev/null -w "%{http_code}\n" -H 'x-user-id: 2' https://localhost:3443/orders/2
# 정상: alice(2)가 자기 주문(id=1) 조회 → 200
curl -sk -o /dev/null -w "%{http_code}\n" -H 'x-user-id: 2' https://localhost:3443/orders/1
# 가격조작 차단: 노트북을 10원에 시도 → 서버가 정가로 재계산해 응답
curl -sk -X POST https://localhost:3443/orders -H 'content-type: application/json' \
  -H 'x-user-id: 2' -d '{"product":"노트북","total":10}'
# 기대: {"id":...,"product":"노트북","quantity":1,"total":1500000}
```

## 7. 흔한 오류 / 확장 과제

**흔한 오류**
- 서버 재계산 없이 클라이언트 가격에 대해 "검증만" 추가 → 여전히 조작 가능. **가격의 출처는 항상 서버 DB**.
- IDOR을 UI 숨김으로만 방어(직접 API 호출로 우회 가능).

**확장 과제 (심화)**
- 결제 멱등성(idempotency key)으로 **중복 결제/재전송 공격**을 방어한다.
- 웹훅 서명 검증(HMAC)으로 위조된 결제 완료 콜백을 차단하는 로직을 구현한다.
