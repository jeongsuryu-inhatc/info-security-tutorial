# 5주차 실습 — 코드보안

## 1. 학습 목표

- 정적 분석 도구(SAST)로 코드 취약점을 자동 탐지하고 리포트를 해석할 수 있다.
- 입력 검증 부재로 생기는 대표 취약점(경로 순회·커맨드 인젝션·프로토타입 오염)을 이해한다.
- **스키마 기반 검증(zod)**과 회귀 테스트로 취약 함수를 안전하게 만들 수 있다.

## 2. 사전 준비물

- Node.js 20, npm
- 스타터 자산: `starter/shopguard-app/` (취약 유틸 함수 3종 포함)
- 도구: [Semgrep](https://semgrep.dev), `eslint-plugin-security`, `zod`, Jest/Vitest
- 선행 지식: JS 모듈, 단위 테스트 기본

## 3. 수업 중 랩 (60분)

> 스타터: `starter/shopguard-app/utils.js` (취약 유틸 3종)

**Step 0.** 프로젝트 루트에서 제출 폴더를 만든다(정적분석 결과를 여기에 저장).
```bash
cd /path/to/workISTutorial
mkdir -p week05
```

### Lab 5-A. 정적 분석 실행 (30분)

**Step 1.** Semgrep으로 스캔한다. Semgrep은 Python/Docker 도구다(npm 아님).
**Docker 방식(권장, 로컬 설치 불필요)**:
```bash
docker run --rm -v "$PWD:/src" semgrep/semgrep \
  semgrep --config=auto /src/starter/shopguard-app 2>&1 | tee week05/semgrep-before.txt
```
Docker가 없으면 pip로 설치해 실행한다:
```bash
python3 -m pip install --user semgrep
semgrep --config=auto starter/shopguard-app 2>&1 | tee week05/semgrep-before.txt
```

**Step 2.** ESLint 보안 플러그인으로도 스캔한다(앱 폴더에 로컬 설치 후 실행).
```bash
cd starter/shopguard-app
npm install --no-save eslint@8 eslint-plugin-security@1
cat > .eslintrc.json <<'EOF'
{ "plugins": ["security"], "extends": ["plugin:security/recommended"],
  "parserOptions": { "ecmaVersion": 2022, "sourceType": "script" } }
EOF
npx eslint utils.js routes/orders.js auth.js 2>&1 | tee ../../week05/eslint-before.txt || true
cd ../..
```

**Step 3.** 탐지된 경고를 **심각도별로 분류**하고, 각 경고가 가리키는 코드 위치를 기록한다.
오탐으로 판단되는 항목 1개를 골라 근거를 적는다.

### Lab 5-B. 취약 함수 3종 재현 (30분)

**Step 4.** REPL로 세 취약점을 실제로 재현한다.
```bash
cd starter/shopguard-app
node -e "console.log(require('./utils').readUpload('../../../etc/passwd').slice(0,100))"   # 경로 순회
node -e "console.log(require('./utils').makeThumb('a.png; id'))"                            # 커맨드 인젝션(echo로 시연)
node -e "const {merge}=require('./utils'); const o={}; merge(o, JSON.parse('{\"__proto__\":{\"isAdmin\":true}}')); console.log(({}).isAdmin)"  # 프로토타입 오염 → true
```

**Step 5.** 정상 입력도 확인해 대비한다.
```bash
node -e "console.log(require('./utils').readUpload('product-101.txt'))"   # 정상: 파일 내용 반환
```

**랩 제출물**: Step 1 Semgrep 경고 분류표 + Step 4 세 취약점 재현 캡처(특히 `isAdmin → true`).

## 4. 주간 과제 (2.5시간)

**진행 방식**: `starter/shopguard-app/utils.js`를 **직접 수정**하고, 같은 폴더에
`utils-test.js`를 작성한다(그래야 아래 명령과 자동채점이 그대로 동작한다). 완료 후 제출용으로 복사한다.

1. **입력 검증**을 추가한다(`starter/shopguard-app/utils.js` 편집).
   - 경로 순회: `path.basename()` + 허용 디렉터리 화이트리스트 검사
   - 커맨드 인젝션: `execFile`(인자 배열) 사용 + 파일명 `zod` 스키마 검증
   - 프로토타입 오염: `__proto__`/`constructor` 키 차단 또는 `Object.create(null)`
2. **회귀 테스트**를 작성하고 실행한다: 악성 입력은 거부(throw), 정상 입력은 통과.
   ```bash
   cd starter/shopguard-app
   node --test utils-test.js        # 전부 pass 확인
   cd ../..
   ```
3. Semgrep을 재실행해 경고가 사라졌음을 캡처한다(Step 1의 Docker/pip 명령 재실행 → `week05/semgrep-after.txt`).
4. 제출용으로 복사한다.
   ```bash
   cp starter/shopguard-app/utils.js       week05/utils-safe.js
   cp starter/shopguard-app/utils-test.js  week05/utils-test.js
   ```

## 7. 흔한 오류 / 확장 과제

**흔한 오류**
- 경로 순회 방어를 `replace('..','')`로 처리 → `....//` 우회 가능. 정규화 후 검증이 원칙.
- `execFile`을 쓰면서 shell 옵션을 켜 인젝션 부활.

**확장 과제 (심화)**
- CI(GitHub Actions)에 Semgrep을 붙여 **PR마다 자동 스캔**되게 구성한다.
- `npm audit` / Snyk로 **의존성 취약점(SCA)**을 점검하고 취약 패키지 1개를 업그레이드한다.
